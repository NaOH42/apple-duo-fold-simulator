# Apple DUO 折叠模拟器

手机优先、以 iPhone Duo 外观为参考的物理玩具。抓住机身，甩动、折叠、抛掷，或挑战完整开合的本机纪录。

模型依据 Apple [官方技术规格](https://www.apple.com.cn/iphone-duo/specs/)的宽高厚比例及[产品页官图](https://www.apple.com.cn/iphone-duo/)重做，包含星光白背部双摄、无后摄半边的完整外屏、连续内屏与包覆式轴盖。模型由程序构建，并非官方 CAD 或扫描模型，不代表逐零件 1:1 还原。参考图片仅保存在 `output/` 供对照，不进入运行包。

## 直接玩

[在线游玩](https://naoh42.github.io/apple-duo-fold-simulator/) · [GitHub 源码](https://github.com/NaOH42/apple-duo-fold-simulator)

Windows 双击 `启动游戏.cmd`，浏览器会在服务器就绪后打开 `http://localhost:4173/`。保持启动窗口打开；关闭窗口即停止。需要本机已有 Node.js。

启动窗口也会显示同一 Wi-Fi 的手机地址。真实手机能否访问还取决于网络与系统防火墙；项目不会自动修改系统设置。

网页必须通过本地服务器打开，不能直接双击 `dist/index.html`。

## 操作

- 按住可见的机身表面拖动；抓角落更容易带来翻转。甩动让另一半靠惯性开合，松手后自然落下。
- 上拖直接提起机身，不会随着反复抓放把手机推向桌面远处；台面刻线和落地阴影提供固定参照。
- 两块内屏朝向你、两处抓点均可见时，可双指各抓一半。抓住以后转到背面不会突然松手。
- 电脑双手：按住 Shift，单击一个内屏，松鼠标留下抓点；再拖另一半。松 Shift 释放留下的抓点。
- “换新”清除损坏和本局进度。右上“更多”可切换模式、开关声音、查看玩法和本机纪录；模式切换同样从新机开始。
- 自由模式可以摆弄损坏后的残骸；耐久挑战在屏幕完全失效或铰链断开时结束。
- 内外屏的锁屏时间和中文日期跟随玩家设备的本地系统时间与时区，跨分钟、跨日和系统调时后更新；不需要联网或额外权限。
- 开合时显示内容会在清晰画面与毛玻璃之间平滑变化，配合内外屏亮度交接；中途反向折叠可连续回退。玻璃字带轻微壁纸折射和渐变高光。

## 积分与耐久

展开至少155° → 合拢不超过25° → 再展开至少155°算一次完整开合，基础100分。动作平顺且无损伤多25分；6秒内连续完成逐次增加0.1倍，最高2倍。停顿或受伤重置倍率。

正常开合及静置不掉耐久。猛烈开合、抵限硬掰和高强度撞击分别导致铰链或屏幕损伤，不会自动修复。

主动收手奖励为 `累计分 × 20% × 较低的剩余耐久比例`。折坏保留累计得分。本机纪录只记录耐久挑战，清理浏览器数据会清除纪录。力道与损坏是游戏标定，不对应真实产品测试数据。

## 开发

```powershell
npm ci
npm run dev
npm test
npm run build
```

Vite + TypeScript + Three.js + Rapier 3D。物理固定步长1/120秒，动态双机身、真实作用点抓取、单轴铰链、CCD；不自动摆正或固定机身。外观、壁纸、裂纹和声音由本项目程序生成，运行时无外部素材请求。

生产包在 `dist/`，入口为 `index.html`，所有路径相对。`scripts/serve.mjs --base=/toy/apple-duo/` 可检查子目录访问（默认4173端口，PORT可设置）。

`output/playwright/` 保存本次浏览器截图和可重复的验证脚本；测试源码在 `tests/`。开发地址加 `?qa=1` 仅在开发模式暴露诊断对象，生产包不含测试控制入口。

## 手机版与 GitHub Pages

- 适配320–430px竖屏和低矮横屏，遵循动态视口与刘海/底部手势安全区；按钮至少44px，结算卡可滚动，图片可长按保存。
- 自由模式只常驻标题、更多和换新，抓住时显示力道；挑战才显示次数、分数和耐久。初次上手提示会自动收起。
- 手机渲染分辨率上限1.5倍；低资源设备1.25倍并降低阴影分辨率，画布总像素不超过250万。该预算不改变物理或计分规则。
- 开合过渡只更新显示参数，模糊纹理预先生成；同一分钟不重绘或上传时钟纹理。缺少Canvas滤镜的浏览器使用缩小再重构的柔化兼容路径。
- 先显示轻量界面，再并行加载3D与物理引擎，避免首开长时间白屏；横竖屏和浏览器工具栏变化时同步实际画布尺寸。
- 源码在`main`分支，静态网页在`gh-pages`分支。构建并提交源码后，明确执行`node scripts/publish-pages.mjs`发布；脚本只向本项目仓库推送，不写全局Git配置，不强制推送，保留旧指纹资源以兼容已打开页面。
- GitHub Pages发布源为`gh-pages`的根目录，无需项目自定义CI配置。上线以Pages构建状态、线上资源哈希和实际浏览器检查为准。

## 交付与验证边界

`artifacts/` 内为可上传的静态网页ZIP及校验清单。自动化规则、实际物理世界和桌面浏览器模拟触摸属于工程验证；真实 Android/iPhone 双指手感、低端机性能和 Toy 内嵌预览需分别验收。

本项目未上传或提交 Toy 审核。Rapier兼容包内嵌WASM；实际 Toy 的运行环境兼容性要通过平台预览确认。当前 Rapier 上游初始化会输出一条弃用提示，不影响本次运行；不修改或屏蔽依赖检查。
